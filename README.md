# AI Client Report Generator (VPf10)

Превращает расшифровку разговора с клиентом турагентства в готовый PDF-отчёт.

Работает в четыре шага: читает текст диалога → просит модель вернуть структурированный JSON →
проверяет данные схемой → подставляет их в HTML-шаблон и конвертирует в PDF через WeasyPrint.
Шаблон отделён от данных: меняется вёрстка — код не трогаем.

## Как это выглядит

```
samples/dialog_turkey.txt
   → модель (gpt-4o-mini) → JSON
   → pydantic-проверка
   → templates/request.html → HTML
   → WeasyPrint → reports/report_2026-11-17_09-31_request.pdf
```

Примеры готовых отчётов — в папке `examples/`:
`example_request.pdf` (заявка на подбор тура) и `example_summary.pdf` (сводка звонка).

## Два типа отчёта

| Тип | Шаблон | Назначение |
|---|---|---|
| `request` | `templates/request.html` | заявка на подбор тура: параметры поездки, пожелания, риски, шаги, блок «уточнить» |
| `summary` | `templates/summary.html` | сводка звонка: тема, суть запроса, настроение, договорённости |

Данные для обоих типов одни и те же — различается только макет.

## Схема данных

| Поле | Тип | Правила |
|---|---|---|
| `client_name` | строка | имя клиента или «не указано» |
| `contact` | строка | телефон, мессенджер, почта |
| `country`, `city` | строка | куда едет |
| `dates` | строка | как назвал клиент |
| `nights` | целое 1–60 или null | число ночей |
| `people` | целое 1–20 или null | число человек |
| `budget` | число или null | рубли |
| `preferences` | список до 6 | конкретные пожелания |
| `topic`, `main_request` | строка | тема и суть обращения |
| `mood` | строка | настроение клиента |
| `risks` | список до 5 | возражения и риски |
| `next_steps` | список до 6 | договорённости |
| `manager` | строка | менеджер |
| `confidence` | число 0–1 | уверенность извлечения |

`ReportData.missing_fields()` считает пропуски кодом, а не моделью: если бюджета нет,
он попадёт в блок «Уточнить у клиента», но отчёт всё равно соберётся.

## Запуск

```cmd
cd "C:\Users\<ваш путь>\VPf10"
py -m venv .venv
.venv\Scripts\activate.bat
pip install -r requirements.txt
copy .env.example .env
python main.py samples\dialog_turkey.txt
```

В `.env` нужен `PROXYAPI_KEY`.

Команды:

```cmd
python main.py samples\dialog_turkey.txt                    # заявка (тип по умолчанию)
python main.py samples\dialog_cyprus.txt --type summary     # сводка звонка
python main.py samples\dialog_short.txt --json-only         # только JSON в консоль
python main.py --interactive                                # вставить текст вручную
python main.py samples\dialog_turkey.txt --out my_reports   # свой каталог
```

## Надёжность

- **Разбор ответа.** Код снимает ```-обёртки и берёт первый законченный JSON-объект,
  корректно пропуская фигурные скобки внутри строк.
- **Валидация.** pydantic проверяет типы и границы: `nights` 1–60, `people` 1–20,
  `budget > 0`, `confidence` 0–1. Числа из текста вида «150 000 ₽» и «7 ночей» приводятся к числам.
- **Один повтор.** Если JSON не разобрался или не прошёл проверку, уходит второй запрос
  с текстом ошибки. Если и он не помог — код возврата 1 и понятное сообщение.
- **Коды возврата.** 0 — успех, 1 — модель не дала данных, 2 — ошибка ввода
  (нет файла, пустой файл, не UTF-8, слишком длинный текст).
- **Логи.** Четыре этапа с временем и токенами; файл `app.log`.

## Тесты

```cmd
pytest
```

36 тестов: схема данных (границы, приведение чисел, списки, пропуски), разбор JSON
(обёртки, вложенность, скобки в строках), повтор при ошибке, рендер обоих шаблонов,
создание PDF, блок «Уточнить у клиента».

## Структура

```
main.py                 CLI: аргументы, четыре этапа, коды возврата
app/config.py           настройки из .env
app/prompts.py          system prompt и повторный запрос
app/models.py           схема отчёта + missing_fields
app/ai_processor.py     запрос к модели, разбор JSON, повтор
app/pdf_generator.py    Jinja2 → HTML → PDF
app/reports.py          имена файлов, сохранение JSON
templates/              request.html, summary.html
samples/                три диалога для проверки
examples/               два готовых PDF
tests/                  36 тестов
```

## Ограничения

- на входе текст, а не аудио: распознавание речи не подключено;
- нет HTTP-API и очереди: один запуск — один отчёт;
- изображения и диаграммы в отчёты не вставляются;
- качество извлечения зависит от модели: суммы и даты нужно проверять глазами
  (об этом же предупреждает колонтитул в PDF).
