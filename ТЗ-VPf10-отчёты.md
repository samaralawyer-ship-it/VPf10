# ТЗ: AI Client Report Generator (PDF-отчёты из диалогов)

Учебный проект по уроку **VPf10 «Кейс 2: AI-автоматизация»**.
Версия 1.0. Сдача — репозиторий, примеры PDF и скриншоты.

## 1. Цель

Принимать текст разговора с клиентом турагентства, превращать его в проверенный
структурированный JSON и выпускать готовый PDF-отчёт по корпоративному шаблону.

Главная идея: шаблон отделён от данных. Меняется шаблон — не трогаем код; меняется
источник данных — не трогаем вёрстку.

## 2. Вход и выход

**Вход:** текстовый файл с диалогом (`samples/*.txt`), реплики в формате «Клиент: …»,
«Менеджер: …». Аудио не требуется — по заданию на вход идёт уже расшифровка.

**Выход:**

- `reports/report_<дата>_<время>_<тип>.pdf` — готовый документ;
- `reports/report_<дата>_<время>_<тип>.json` — те же данные в JSON (для проверки и отладки).

## 3. Стек и замены

| В уроке | У нас | Почему |
|---|---|---|
| OpenAI / Claude | ProxyAPI, `gpt-4o-mini` | один ключ на все проекты; Gemini в тарифе недоступен (`400 Model not supported`) |
| Jinja2 | незаменимо, 3.1.6 | проверено |
| WeasyPrint | 70.0 | проверено: кириллица и таблицы рендерятся в PDF |
| Flask (опционально) | **не берём** | задание не требует, CLI достаточно |
| `python-pptx` | не берём | в ДЗ нет презентаций |

Дополнительно: `pydantic` для валидации JSON (в уроке нет — это наша страховка),
`httpx` для запросов, `python-dotenv`.

## 5. Схема данных

Одна модель на оба типа отчёта.

| Поле | Тип | Правила |
|---|---|---|
| `client_name` | str | обязательное, непустое |
| `contact` | str | по умолчанию «не указано» |
| `country`, `city` | str | по умолчанию «не указано» |
| `dates` | str | как сказал клиент («10–17 июля») |
| `nights` | int или null | 1–60 |
| `people` | int или null | 1–20 |
| `budget` | float или null | больше нуля, в рублях |
| `preferences` | list[str] | до 6 пунктов, каждый до 120 символов |
| `topic` | str | тема обращения, одна строка |
| `main_request` | str | суть запроса, 1–2 предложения |
| `mood` | str | настроение клиента |
| `risks` | list[str] | до 5 пунктов |
| `next_steps` | list[str] | до 6 пунктов |
| `manager` | str | имя менеджера или «не указано» |
| `confidence` | float | 0–1, уверенность извлечения |

«Чего не хватает» не спрашиваем у модели: список вычисляется кодом из пустых полей.
Это надёжнее — модель не может «забыть» про пропуск.

## 6. Два типа отчёта

| Тип | Шаблон | Что печатает |
|---|---|---|
| `request` | `request.html` | карточка клиента, параметры поездки таблицей, пожелания, бюджет, риски, следующие шаги, блок «уточнить» |
| `summary` | `summary.html` | тема и суть запроса крупным текстом, настроение, риски, договорённости, список уточнений |

Оформление: A4, поля 18 мм, шрифт без засечек 11 pt, цветной заголовок, таблица с границами,
колонтитул с датой и пометкой «сгенерировано автоматически». Без внешних картинок и шрифтов —
чтобы PDF собирался офлайн.

## 7. Надёжность

1. **Разбор ответа.** Модель просят вернуть только JSON. Код снимает ```-обёртки, находит
   объект от первой `{` до последней `}` и парсит.
2. **Валидация.** pydantic проверяет типы и границы: `nights` 1–60, `people` 1–20,
   `budget > 0`, `confidence` 0–1, списки обрезаются до лимитов.
3. **Один повтор.** Если JSON не разобрался или не прошёл валидацию, отправляется второй
   запрос с текстом ошибки. Больше не повторяем — чтобы не жечь токены.
4. **Коды возврата.** 0 — успех, 1 — модель не дала корректных данных, 2 — ошибка ввода
   (нет файла, пустой файл, неизвестный тип).
5. **Пустые значения.** Модели прямо сказано: если данных нет — ставь «не указано» / null,
   не выдумывай.

## 11. Критерии приёмки

| № | Критерий | Как проверить | Признак |
|---|---|---|---|
| 1 | Тесты проходят | `pytest -q` | все `passed` |
| 2 | Отчёт создаётся | `python main.py samples/dialog_turkey.txt` | в `reports/` появились `.pdf` и `.json` |
| 3 | PDF корректный | открыть файл | кириллица, таблица, 1–2 страницы, без «квадратов» |
| 4 | Второй тип | `--type summary` | другой макет, те же данные |
| 5 | Только JSON | `--json-only` | JSON в консоли, PDF не создан |
| 6 | Валидация | `pytest tests/test_models.py` | `nights=0` и `confidence=2` отклоняются |
| 7 | Повтор при битом JSON | `pytest tests/test_ai_processor.py` | второй запрос уходит, при неудаче — исключение |
| 8 | Ошибки ввода | `python main.py нет_файла.txt` | сообщение, код возврата 2 |
| 9 | Логи этапов | вывод команды | четыре шага с временем и токенами |
| 10 | Пропуски честные | `--type request` на `dialog_short.txt` | в блоке «уточнить» непустой список |
| 11 | Секретов в коде нет | поиск `sk-` в `*.py` | пусто |
| 12 | Данные не в репозитории | `git status` | `reports/`, `.env`, `*.log` не в индексе |

## 12. Что не входит

- распознавание аудио (Whisper/SpeechKit) — по заданию на входе текст;
- Flask/HTTP API;
- презентации PPTX;
- изображения, сгенерированные ИИ;
- база данных и очередь задач.

## 13. Бюджет сложности

Одна модель данных, два шаблона, один повтор, четыре этапа с логами. Новое допускается,
только если усиливает проверяемость: тесты валидации и разбора JSON, вычисление пропусков,
коды возврата.
